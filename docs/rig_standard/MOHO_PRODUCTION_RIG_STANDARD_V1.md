# MOHO_PRODUCTION_RIG_STANDARD_V1

Выведен из 20 эталонных ригов (fixtures/rig_library, форензика в forensics/).
Каждое правило имеет ссылку на доказательство. Пометки: [A] универсальный
паттерн, [E] образцовый, [D] не копировать.

## 1. Организация проекта

- Проект: zip, Project.mohoproj, version 1038–1045. [20/20]
- Глубина иерархии слоёв: 3–7. Глубже 7 — признак нечитаемости. [A]
- Имя слоя несёт состояние и сторону: `Boot down`, `sleeve down`, `Body up R`,
  `1/4 R`, `Side L`. [Girl, Dad, astronaft] [A]
- Зеркальные половины — явные копии с суффиксом `_2`/`Dup`, не зеркальный флаг:
  `Forearm R start_2`, `B75 Dup`. [Girl: 180 dup-костей] [A]
- Корень персонажа — одна группа верхнего уровня с BoneLayer-скелетом. [A]

## 2. Скелет

- Иерархия: `Main → Pelvis → Body → Neck → Head`; `Pelvis → Thigh L/R →
  Shin → Foot`; `Body → UpperArm → LowerArm`. [Girl, Mr.Stu, mannequin, Normann] [A]
- binding_mode = 1 во всех скелетах всех эталонов. [20/20] [A]
- Кости-управляшки именуются по функции: `Mouth Switch`, `Leg bend L`,
  `Foot rol R`, `Head Squash`, `Pelvis Switch`. [Girl, Dad, Pioneer] [A]
- Технические кости без имени (`B2`, `B75`) допустимы только внутри
  деформерных цепочек; в Girl они соседствуют с именованными — это минус
  читаемости, не повторять. [D]
- `ik_lock=true` стоит у всех костей всех ригеров — это дефолт Moho, не решение.
  Не считать сигналом. [D-игнор]
- Ограничения углов (constraints + min/max) — на диалах и на суставах
  конечностей. [Girl: 42 кости] [A]
- Динамика костей (bone_dynamics) — выборочно, для волос/юбок/антенн:
  Pioneer 18, Dad 9. Включённая всем скелетом (Girl 297) — случайность. [D]
- Кривые деформеры конечностей — пары `X start` / `X end`:
  `Forearm R start/end`, `Hips R start/end`, `Upperarm R start/end`.
  Присутствуют во всех вылизанных ригах (Girl, Normann, alien, astronaft,
  mannequin, Test leg). [E]

## 3. Биндинг

ДВА режима (доказано файлами):
- **Продакшн (20/20 тяжёлых ригов): binding_mode=1, НОЛЬ явных привязок** —
  у всех арт-слоёв parent_bone=-1 (Girl 362, Dad 294, astronaft 474 слоёв).
  Moho сам назначает влияние по близости к костям; радиус влияния управляется
  полем strength кости. Кривой сгиб конечностей возникает автоматически от
  пар start/end внутри зоны авто-весов.
- **Туториальный/cutout (gramps): binding_mode=2 + явный parent_bone** на
  каждом слое — детерминированно, для растровых частей.
- Слои-деформеры (start/end): hidden=true, shy=true, strength=0,
  ignored_by_ik=true — не участвуют в биндинге и IK, только в деформации.
- Image-слои при явной привязке: origin слоя в корне кости, картинка
  удерживается транслейтом в локальных координатах.

Смарт-каналы (вскрыто на mannequin): ЛЮБОЙ канал (anim_scale/anim_angle/
anim_pos кости, transforms/switch_keys слоя) может нести `actions`:
`[{name: <имя экшена диала>, pose: {type,when,val,interp}}]` — значения
канала на каждой позе диала. Этим же механизмом диал переключает активную
IK-кость: skeleton.bones_groups[].active_bone несёт actions.

## 4. Смарт-кости (диалы)

Формула (дословно из Girl):
- Диал = кость, у `anim_angle.actions = [{name, pose{when[],val[]}}]` —
  ключевые углы. У Girl 36 диалов.
- Свитч: у `switch_keys.actions = [{name: <то же имя>, pose{when,val}}]` —
  на угле диала свитч показывает заданное состояние. Связь — ПО ИМЕНИ action.
- Диапазоны: поворот головы 9 поз, −45°..270° (Girl, alien, astronaft,
  mannequin — идентично; Dad/Pioneer — тот же span 315° в другой фазе). [E]
- Карта видов Girl: `Front, Back, 1/4 R, Side R, 3/4 R, Front, 3/4 L, Side L,
  1/4 L` — полный оборот через спину и обратно. [E]
- Категории по частоте: head(24), foot(22), leg(20), arm(10), eye/brow/mouth(8).
- Симметрия: диалы дублируются на L/R (`Foot rol L/R`, `Hands_r/L`).

## 5. Свитчи

- 2 состояния — доминируют (120 шт): куртки/рукава/присоединения. [A]
- 8 состояний — головы/тела (виды поворота). [A]
- 3–6 — рты, брови, ступни. Рты у Girl: 4 состояния × несколько ракурсов;
  у astronaft рот до 12 состояний.
- Имена состояний — вид/фона: `Front`, `3/4 R`, `Wide`, `Closed`.

## 6. Маски и порядок

- Маски — массовая техника швов: astronaft 104, Dad 100, Girl 93,
  football_player 73. [A]
- Порядок слоёв статичен и выстроен по глубине: дальняя рука (низ) → дальняя
  нога → торс → ближняя нога → голова → ближняя рука (верх).
  [gramps эталон; подтверждено Girl/astronaft] [A]
- Переключение порядка при движениях — через диалы `Leg order`, `sort arm`. [A]

## 7. Аниматорский контракт

- Аниматор трогает: диалы с говорящими именами, кости конечностей, Main.
- Скрыто от аниматора: технические деформеры, служебные свитчи, маски.
- Нейтраль диала — поза index 0 (обычно Front).
- Диапазоны диалов ограничены constraints — аниматор не может вывернуть
  систему. [A]

## 8. Надёжность и редактируемость

- Комбинации контролов не должны конфликтовать: диалы действуют на свои
  системы через именованные экшены, пересечения минимальны.
- Другой ригер читает риг по именам: `X Switch` (выбор рисунка),
  `X bend` (коррекция сгиба), `X rol` (перекат), `X order` (порядок),
  `X Squash` (сжатие). [A]

## 9. Vitruvian Bones (Витрувианские кости)

- Группы альтернативных скелетных цепочек (`vitruvian_group`, `is_vitruvian: true`) для стоп (`Foot_L_Front`, `Foot_L_34`, `Foot_L_Side`) и кистей (`Hand_Open`, `Hand_Fist`, `Hand_Point`). [E - Borsch Урок 5]
- Позволяет мгновенно переключать ракурсы конечностей без создания десятков дублирующих костей на таймлайне аниматора. [A]

## 10. Сетки триангуляции (Delaunay Smart Mesh)

- 2D меш деформации (`Smart Mesh`) с автоматической триангуляцией Делоне.
- Применяется в зоне паха (`Crotch_SmartMesh`) для устранения артефактов при подъеме ног и на торсе/одежде для плавных органических изгибов. [E - Borsch Урок 5, 7]

## 11. Автоматизация и MCP Pipeline (`mohorig:golden`)

- **Прямая headless-компиляция**: генерация бинарных `.moho` ZIP-архивов с чистым `Project.mohoproj` JSON (v1045) без необходимости запуска GUI Moho.
- **MCP Tools**: `moho.rig.build_full_turnaround_rig`, `moho.rig.synthesize_smart_actions`, `moho.rig.build_mesh_warp`, `moho.rig.audit_animator_contract`, `moho.project.compile_to_file`.
- **Golden Path Evidence**: `npm run mohorig:golden` генерирует детерминированный артефакт в `docs/evidence/moho-turnaround-golden-path/`.
