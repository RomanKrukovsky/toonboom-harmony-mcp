# Подключение MCP-сервера: Harmony и Moho

Инструкция для человека, который хочет, чтобы просто заработало.

Сервер один, а пакетов анимации два. Какой из них обслуживать, решает переменная
окружения `ANIM_HOST` в момент запуска:

| `ANIM_HOST` | Что получите | Префикс тулов |
| --- | --- | --- |
| `harmony` | Toon Boom Harmony, 570 тулов | `harmony.` |
| `moho` | Moho, 59 тулов | `moho.` |

Оба набора одновременно сервер не отдаёт никогда — и это не недоделка, а
осознанное решение. Подробнее в разделе [Почему не оба сразу](#почему-не-оба-сразу).

---

## Шаг 1. Соберите сервер

```bash
cd /Users/romanmolodyko/Documents/toon-boom-harmony-mcp
npm run build
```

Команда собирает TypeScript в JavaScript. Результат — файл `dist/index.js`,
именно его и запускает клиент. Проверьте, что он появился:

```bash
ls -la dist/index.js
```

Если файла нет — дальше идти бессмысленно, клиент не сможет запустить сервер.

---

## Шаг 2. Впишите конфигурацию

Файл конфигурации Claude Code лежит здесь:

```
~/.claude.json
```

Внутри найдите раздел `mcpServers` и добавьте туда две записи. Готовый пример
лежит в корне репозитория — [`.mcp.json.example`](../.mcp.json.example).
Скопируйте оттуда содержимое `mcpServers` (поля, начинающиеся с подчёркивания,
можно не переносить — это пояснения, JSON не поддерживает комментарии).

Коротко, как выглядят две записи:

```json
"anim-harmony": {
  "type": "stdio",
  "command": "node",
  "args": ["/Users/romanmolodyko/Documents/toon-boom-harmony-mcp/dist/index.js"],
  "env": { "ANIM_HOST": "harmony" },
  "disabled": false
},
"anim-moho": {
  "type": "stdio",
  "command": "node",
  "args": ["/Users/romanmolodyko/Documents/toon-boom-harmony-mcp/dist/index.js"],
  "env": { "ANIM_HOST": "moho" },
  "disabled": true
}
```

Обратите внимание: `args` у обеих записей **одинаковый**. Это один и тот же
сервер, отличается только `ANIM_HOST`.

Путь обязан быть абсолютным. Клиент запускает сервер из неизвестного рабочего
каталога, и относительный путь вида `./dist/index.js` просто не найдётся.

После правки перезапустите Claude Code — конфигурация читается на старте.

## Шаг 3. Удалите старую запись `moho-mcp`

**Это обязательный шаг.** В вашем `~/.claude.json` есть запись `moho-mcp`, которая
указывает на переехавший репозиторий:

```json
"moho-mcp": {
  "command": "node",
  "args": ["/Users/romanmolodyko/Documents/Codex/2026-05-10/https-github-com-kveto-mohomcp-codex/bridge/dist/index.js"],
  "env": { "MOHO_MCP_IPC_DIR": "/tmp/moho-mcp" },
  "disabled": true
}
```

Ищите её по точному пути `Codex/2026-05-10/https-github-com-kveto-mohomcp-codex`.
Запись нерабочая сразу по двум причинам:

1. **Путь битый.** Каталог `2026-05-10/` сейчас пуст — код Moho-моста переехал
   в этот проект, в `src/moho/`. Проверить можно так:
   ```bash
   ls /Users/romanmolodyko/Documents/Codex/2026-05-10/
   ```
   Каталог отдаёт пустоту. Файла `bridge/dist/index.js` там нет.
2. **Она отключена** (`"disabled": true`), так что даже с целым путём не
   запустилась бы.

Что делать: **удалите** запись `moho-mcp` целиком, её заменяет `anim-moho` из
шага 2. Оставлять её бессмысленно — при попытке включить она упадёт с
`Cannot find module`.

Заодно обратите внимание на `MOHO_MCP_IPC_DIR: /tmp/moho-mcp` из старой записи.
**Не переносите эту переменную в новую конфигурацию.** Причины в разделе
[Про каталог IPC](#про-каталог-ipc-и-почему-его-лучше-не-задавать).

## Шаг 4. Убедитесь, что заработало

Переспросите у клиента список доступных тулов. Признаки успеха:

- при включённом `anim-harmony` — тулы с префиксом `harmony.`,
  например `harmony.scene.get_info`. Всего **570**;
- при включённом `anim-moho` — тулы с префиксом `moho.`,
  например `moho.document.get_info`. Всего **59**.

Префиксы не смешиваются: если видите оба сразу — включены обе записи, вернитесь
к шагу 2 и отключите лишнюю.

Проверить сервер можно и без клиента, прямо из терминала:

```bash
cd /Users/romanmolodyko/Documents/toon-boom-harmony-mcp
ANIM_HOST=moho node dist/index.js < /dev/null
```

В stderr должна появиться строка:

```
MCP-сервер запущен по каналу stdio: хост moho (ANIM_HOST), тулов 59
```

Эта строка — самая быстрая диагностика: она прямо сообщает, какой хост сервер
считает активным и сколько тулов отдаёт. Прервите выполнение через `Ctrl+C`.

## Как переключаться между Harmony и Moho

Поменяйте значения `disabled` у двух записей местами и перезапустите клиент:

| Работаете в | `anim-harmony` | `anim-moho` |
| --- | --- | --- |
| Harmony | `false` | `true` |
| Moho | `true` | `false` |

Другого способа нет: активный хост фиксируется один раз при старте процесса.
На ходу, не перезапуская сервер, переключить его нельзя.

---

## Почему не оба сразу

Соблазн включить обе записи и «не думать о переключении» понятен, но так делать
не надо. Описания всех тулов уходят в контекст модели при каждом запуске.
570 + 59 = **629 описаний** вместо нужных 59 или 570. Модель начинает хуже
выбирать тул: среди сотен близких по смыслу названий легко промахнуться.

При этом польза от двух наборов сразу нулевая: сервер не умеет и не должен
гонять данные между Moho и Harmony, а человек в один момент времени работает
в одном пакете.

## Про каталог IPC и почему его лучше не задавать

Это относится только к Moho. Harmony каталог IPC не использует.

Сервер общается с Moho через файлы в служебном каталоге. Путь к нему по
умолчанию:

```
~/Library/Application Support/MohoMCP/ipc
```

Ровно этот же путь по той же логике вычисляет и Lua-плагин внутри Moho, поэтому,
**если ничего не задавать, стороны сходятся сами**. Так и рекомендуется.

Переопределить путь можно переменными `MOHO_IPC_DIR` или `MOHO_MCP_IPC_DIR`, но
в этом есть подвох. Плагин работает внутри процесса Moho и переменных окружения
из конфигурации MCP-сервера **не видит**. Если задать переменную только в
конфигурации, сервер уйдёт в один каталог, а плагин останется в другом. Запросы
будут писаться туда, где их никто не читает, и Moho молча перестанет отвечать —
без ошибок, просто тишина. Это самая неприятная поломка из возможных, потому что
она не выглядит как поломка.

Отдельно про `/tmp/moho-mcp` из старой записи: этот каталог доступен всем
пользователям системы, и сервер сам помечает его как небезопасное наследие,
предупреждая в stderr. Путь по умолчанию (`~/Library/...`) приватный. Ещё одна
причина не переносить `MOHO_MCP_IPC_DIR` в новую конфигурацию.

## Типичные грабли

### Правки в коде не подействовали

Клиент запускает `dist/index.js` — собранный файл, а не исходники из `src/`.
Пока не выполнен `npm run build`, ваши правки для клиента не существуют.
После любых изменений в `src/`:

```bash
npm run build
```

и перезапустите клиент.

### `ANIM_HOST` не задан — молча берётся Harmony

Если переменную не указать, сервер не падает и не спрашивает: он берёт
значение по умолчанию `harmony` и отдаёт 570 тулов. Проект исторически про
Harmony, поэтому такое поведение выбрано осознанно.

Практический вывод: **всегда указывайте `ANIM_HOST` явно в обеих записях.**
Иначе, ожидая Moho, вы получите Harmony и будете искать причину, почему «Moho не
работает», хотя Moho просто никто не включал. Проверить, что сервер считает
активным, можно по строке запуска в stderr (см. шаг 4).

### Опечатка в `ANIM_HOST` — сервер падает на старте

`ANIM_HOST=mogo` не запустится. Сервер завершится с кодом 1 и сообщением:

```
Критическая ошибка запуска MCP-сервера: HostConfigError: Неизвестное значение
ANIM_HOST="mogo". Допустимые значения: harmony, moho.
```

Это не баг, а защита. Альтернатива — тихо откатиться к Harmony — гораздо хуже:
вы просите Moho, получаете 570 чужих тулов и не понимаете, почему Moho «не
работает». Громкое падение сразу показывает настоящую причину.

Регистр при этом не важен: `ANIM_HOST=Moho` и `ANIM_HOST=MOHO` работают, значение
приводится к нижнему регистру, лишние пробелы обрезаются. Падение вызывает только
действительно неизвестное значение.

### В списке тулов пусто или клиент пишет об ошибке запуска

Проверьте по порядку:

1. Файл `dist/index.js` существует? Если нет — `npm run build`.
2. Путь в `args` абсолютный и без опечаток? Проверьте буквально:
   ```bash
   ls -la /Users/romanmolodyko/Documents/toon-boom-harmony-mcp/dist/index.js
   ```
3. Не осталась ли включённой старая запись `moho-mcp` с битым путём (шаг 3)?
4. Запустите сервер вручную командой из шага 4 — ошибка запуска будет видна
   в stderr целиком, с текстом и стеком.

### Moho не отвечает, хотя тулы `moho.` видны в списке

Список тулов виден и без запущенного Moho: тулы регистрируются на старте
сервера, независимо от того, отвечает ли приложение. Если тулы видны, но вызовы
не проходят, проверьте:

1. **Moho запущен?** Сервер общается с живым приложением.
2. **Плагин установлен?** Если нет:
   ```bash
   npm run install:moho-plugin
   ```
3. **Не задавали ли `MOHO_IPC_DIR` / `MOHO_MCP_IPC_DIR`** только на одной
   стороне? Это разводит сервер и плагин по разным каталогам, и симптом ровно
   такой: тулы есть, ответов нет. См. раздел
   [Про каталог IPC](#про-каталог-ipc-и-почему-его-лучше-не-задавать).
