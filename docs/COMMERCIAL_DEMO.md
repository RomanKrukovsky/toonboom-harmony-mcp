# Commercial Demo — Moho MCP

Демонстрационный пакет, который показывает, как AI-агент (opencode + Moho MCP) собирает сцену с humanoid speaker в Moho из структурированного `scene_plan.json` за **<2 минуты в offline-режиме**. Без ручной работы, без лицензированного Moho Pro, без фабрикации рендера.

---

## 1. Цель демо

Показать клиенту / продюсеру / студии, что **Moho MCP закрывает рутинный пайплайн сборки сцены** (фон → риг → анимация → камера → эффекты → рендер) и оставляет аниматору только творческую работу.

Демо специально работает в `offline_dry_run` режиме — никакого реального Moho не нужно, никакого пиратства, никакой лжи про «рендер готов». Это **честная симуляция пайплайна**, а не фейк.

---

## 2. Что входит в пакет

Путь: `examples/commercial-demo/`

| Файл / папка | Назначение |
|---|---|
| `scene_plan.json` | Структурированный план сцены для humanoid speaker: фон, риг, действия, камера, эффекты |
| `assets/` | Synthetic placeholders: PSD-слой фона, аудио-дорожка, заглушки рига |
| `templates/` | Reference rig `humanoid_2leg` — эталонная иерархия костей для валидации |
| `README.md` | Краткая инструкция запуска |

---

## 3. Запуск демо (3 команды)

```bash
# 1. Установить MCP
cd /Users/romanmolodyko/Documents/toon-boom-harmony-mcp
npm install && npm run build

# 2. Запустить opencode в этом каталоге
opencode

# 3. В opencode отправить промпт:
# "Собери сцену через moho.factory.run_show_bible"
```

Opencode прочитает `scene_plan.json`, подгрузит `ShowBible` + `Character Bible`, прогонит пайплайн и выдаст финальный отчёт.

## 6. Honest disclaimer (обязательно озвучить)

Демо работает в **`offline_dry_run`** режиме. Это значит:

- Все команды Moho **логируются и валидируются**, но **не выполняются** на реальном Moho.
- Без лицензированного **Moho Pro** финальный шаг (`render`) помечается как `requires_real_moho`.
- Агент **не фабрикует PNG/MP4** — он честно говорит «нужен реальный Moho для финального рендера».
- Это **by design**: мы продаём автоматизацию сборки, а не поддельный рендер.

Клиенту это говорится прямо: *«Мы показываем, что пайплайн сборки работает. Финальный рендер — ваш Moho Pro на вашей машине. Всё прозрачно.»*

## 7. Как записать demo-видео

| Кадр | Что снимать |
|---|---|
| **Screen record** | opencode TUI — ввод промпта, появление логов PIR, approval-запрос, финальный отчёт |
| **Time-lapse** | Сборка сцены от 0 до готовности PIR (ускорить в 4×) |
| **Side-by-side** | Слева — ручная сборка в Moho (4 ч, таймер). Справа — AI-сборка (2 мин, таймер). Видно наглядно. |
| **Overlay** | Таймер + time-savings счётчик в углу |

Рекомендуемая длина ролика: **2:45–3:00**. Дольше — теряется внимание, короче — не успевает сработать «вау-эффект».
