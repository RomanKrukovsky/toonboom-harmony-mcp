# Универсальный MCP: контракт интеграции Moho

Рабочий контракт для параллельной интеграции. Каждый исполнитель владеет
своим списком файлов и НЕ трогает файлы других.

## Решения (согласованы с заказчиком)

1. Один сервер, два хоста. `ANIM_HOST=harmony|moho` при старте выбирает
   активный хост. Отдаётся ровно один набор тулов. Никогда оба.
2. Кросс-приложенческих потоков нет. Данные между Moho и Harmony не ходят.
3. Общей абстракции «универсальный тул» нет. Приложения слишком разные.
4. Нейминг: Moho приводится к `moho.<домен>.<действие>` в snake_case.
   `document_getInfo` -> `moho.document.get_info`.
5. Регистрация: стиль Harmony (`defineTool` + Zod + ручной диспетчер).
   Новый SDK API (`McpServer.tool`) НЕ используется.
6. Инфраструктура Moho (safety engine, observability) переносится как есть
   в `src/moho/`, рядом с Harmony-механизмами. Не объединяется.
7. Репозиторий-источник после переноса — архив. Связь с upstream рвётся.

## Критерий готовности

- `npm run build` и `npm run typecheck` проходят.
- Тесты Moho и Harmony проходят.
- `ANIM_HOST=moho` отдаёт только `moho.*`; `ANIM_HOST=harmony` — только `harmony.*`.
- Живой Moho с установленным плагином отвечает хотя бы на один тул.

## Инвариант нейминга

Имя MCP-тула НЕ равно имени Lua-метода внутри плагина.

| Слой | Пример | Кто владеет |
| --- | --- | --- |
| Имя MCP-тула | `moho.document.get_info` | этот проект |
| Lua-метод в IPC | `document.getInfo` | плагин Moho |

Переименование тулов не должно менять строки Lua-методов, уходящие в
`safeSend(...)`. Ломать этот инвариант запрещено: плагин перестанет отвечать.

## Общий слой (владелец: координатор, НЕ править агентам)

- `src/hostProfile.ts` — чтение `ANIM_HOST`, тип `AnimHost`.
- `src/moho/toolNames.ts` — единая карта старое имя -> новое имя.
- `src/index.ts` — регистрация набора по активному хосту.

## Разделение владения файлами

| Владелец | Файлы |
| --- | --- |
| A1 | `src/moho/tools.ts` — документ + слои |
| A2 | `src/moho/tools.ts` — кости + анимация (после A1) |
| A3 | `src/moho/tools.ts` — меш + batch + system (после A2) |
| B1 | `src/moho/config.ts` |
| B2 | `src/moho/moho-client.ts`, `protocol.ts`, `protocol-version.ts` |
| B3 | `src/moho/security/mohoSafetyEngine.ts` |
| B4 | `src/moho/observability/*` |
| B5 | `src/moho/resources.ts`, `keep-alive.ts` |
| B6 | `src/moho/platform-*.ts`, `*-input.ts`, `*-capture.ts` |
| C1..C4 | `tests/moho/*` (по файлам) |
| D1 | `docs/capability_registry.json` (запись Moho-возможностей) |
| D2 | `package.json`, `jest.config.cjs`, `tsconfig.json` |
| D3 | `scripts/install_moho_plugin.sh`, `moho-plugin/**` |
| D4 | `README.md`, `docs/MOHO.md` |

Файл `src/moho/tools.ts` — единственный, где неизбежна очередь: он один и
большой (1401 строка). Поэтому A1 -> A2 -> A3 идут последовательно, а не
параллельно.

## Правила для всех исполнителей

- Никаких заглушек и `TODO`. Если чего-то не хватает — сообщить, не выдумывать.
- Не менять поведение Harmony-тулов. 561 рабочий тул не трогаем.
- Проверять свою работу командой, а не предположением. `npm run typecheck`
  после правок в TS.
- Русские комментарии там, где уже приняты русские; английские — где
  английские. Не переписывать стиль соседнего кода.
