# Девять подсистем Moho: контракт для параллельной работы

## Что делаем

Добавляем девять недостающих механик Moho. Сверено по 149 встроенным
Lua-скриптам самого приложения (официальная справка — редирект-заглушка).

| # | Подсистема | Почему нужна |
| --- | --- | --- |
| 1 | Камера | Без неё нельзя поставить кадр — только двигать объекты внутри него |
| 2 | Actions | Ключевая механика Moho: цикл ходьбы записывается один раз и переиспользуется |
| 3 | Смарт-кости | Есть один вызов создания, управлять готовыми нельзя |
| 4 | Физика костей | Динамика, пружины, инерция |
| 5 | Частицы | Слой создаём, настроить нельзя |
| 6 | Аудио | GetAmplitude даёт громкость по кадрам — липсинк и реакция на звук |
| 7 | Кривые | Контрольные точки Безье, вес, сегменты |
| 8 | Глубина | DepthSort — сортировка слоёв по глубине |
| 9 | 3D-слои | Единственный из 10 типов, который не создаём |

## Как устроен путь одного тула

Пять слоёв, все обязательны. Пропуск любого = тул не работает.

```
1. moho-plugin/moho_mcp/tools/<область>.lua   обработчик внутри Moho
2. moho-plugin/MohoMCP_Server.lua             регистрация метода (таблица toolModules)
3. moho-plugin/moho_mcp/validator.lua         whitelist Lua-методов
4. src/moho/schemas.ts                        Zod-схема параметров
5. src/moho/tools.ts                          registerTool + safeSend
6. src/moho/toolNames.ts                      карта старое имя -> moho.*
7. src/moho/security/mohoSafetyEngine.ts      whitelist на стороне TS
```

Слои 2, 3, 6, 7 — общие файлы. **Их правит только координатор**, агенты
сообщают, что нужно добавить. Слои 1, 4, 5 делятся по областям.

## КРИТИЧЕСКИЙ ИНВАРИАНТ

Имя MCP-тула НЕ равно имени Lua-метода:

| Слой | Пример | Владелец |
| --- | --- | --- |
| Имя тула | `moho.camera.set_position` | этот проект |
| Lua-метод | `camera.setPosition` | плагин Moho |

Lua-методы: `<область>.<действиеCamelCase>`. Имена тулов:
`moho.<область>.<действие_snake_case>`. Ломать нельзя: плагин знает только
свою половину.

## Обязательные правила Lua-обработчика

Изучи `moho-plugin/moho_mcp/tools/bone.lua` — это образец. Соблюдай:

1. **`moho.document:PrepUndo(layer)` перед КАЖДОЙ мутацией.** Без него
   правка не отменяется через Cmd+Z внутри Moho, а наш журнал операций —
   это аудит, он ничего не откатывает. Пропуск = потерянная работа человека.
2. **`moho.document:SetDirty()` после мутации** — иначе Moho не считает
   документ изменённым и не предложит сохранить.
3. **Каждый вызов API через `pcall`.** Moho падает молча: неверный индекс
   кости уронит скрипт внутри приложения, а мост получит таймаут вместо
   внятной ошибки.
4. **Проверять диапазоны индексов** (`0..count-1`) и тип слоя перед приведением.
5. **Возвращать `nil, "текст ошибки"`** при отказе, а не бросать.
6. Комментарии в Lua английские — как в существующих файлах.

## Правила TS-стороны

- Схема на каждый тул в `schemas.ts`, границы значений реальные (не `z.any()`).
- `describe()` на каждом поле: описание уходит в контекст модели.
- Разрушающие операции (удаление, перезапись) — через `previewHash`.
- Комментарии в `src/moho/*` английские.

## Чего НЕ делать

- Не выдумывать методы Moho API. Если не нашёл в
  `/Applications/Moho.app/Contents/Resources/Support/**/*.lua` — сообщи, не
  придумывай. Выдуманный вызов = таймаут у человека без объяснения.
- Не помечать возможности проверенными: живой Moho сейчас не отвечает
  (опрос внутри приложения включается вручную). Всё новое = не проверено.
- Не трогать файлы вне своей области.

## Как проверять

```
npx tsc --noEmit                 # 0 ошибок
npx jest tests/moho              # проходит
lua -e "assert(loadfile('путь'))"  # синтаксис Lua, если lua доступен
```

Живой Moho проверить нельзя — опрос не запущен. Это ожидаемо.
