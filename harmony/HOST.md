# Хост: Blender вместо Harmony

## Почему сменили хост

Harmony Premium 25.0.0 установлен, но **лицензии нет**:

```
Cannot find license file.
Filename: /usr/local/flexlm/licenses/license.dat
FlexNet Licensing error: -1,359. System Error: 2 "No such file or directory"
```

Каталога `/usr/local/flexlm` не существует вообще. Следствия:
`-batch -script` отказывается стартовать, GUI открывается без рабочего
окна (`screencapture -l <pid>` → «could not create image from window»),
сцену открыть или сохранить нельзя. Владелец подтвердил: установка
никогда не была лицензирована. **Кодом это не лечится.**

Blender 5.1.1 установлен, headless Python работает, лицензия не нужна.
Проверено сразу, до написания кода: `blender -b --python-expr` печатает
версию и выполняет `bpy`.

## Что умеет Blender-хост

| нужно cutout-конвейеру | в Blender |
|---|---|
| плоские части с плоской заливкой | полигоны + Emission-материал |
| FK-иерархия с пивотами | parent-child, `location` = пивот в координатах родителя |
| порядок отрисовки (слои) | смещение по Y (глубина), ортокамера |
| тайминг с явными изингами | keyframes + `interpolation='LINEAR'` |
| рендер без GUI | `blender -b`, EEVEE |
| настоящая рисованная линия (потом) | Grease Pencil |

## Архитектура

Тот же принцип, что задумывался для моста Harmony: **внутри хоста —
максимально тупой код, вся логика снаружи**.

```
движок (columns/craft/rigging/camera)
      |  строит BSceneSpec
      v
  scene_spec.json
      |  blender -b --python blender/build_scene.py
      v
  .blend + PNG-секвенция  ->  ffmpeg -> mp4
```

JSON, а не прямые вызовы `bpy`, потому что `bpy` существует только
внутри процесса Blender — снаружи его не импортировать.

- `blender_host.py` — снаружи: спека сцены, трансляция каналов движка,
  запуск, проверка доступности хоста ДО работы. 12 тестов.
- `blender/build_scene.py` — внутри Blender: читает спеку, строит,
  рендерит. Никакой семантики ремесла здесь нет.

## Доказательства контакта с живым приложением

Впервые в проекте код доехал от движка до пикселей в настоящем
приложении. Две пробы, обе проверяют результат ЧИСЛАМИ по рендеру:

```
python3 smoke_blender.py
  PASS: arm swung dx=-55.3 dy=-60.6 — parenting, pivots, rotation and render all work

python3 smoke_engine_to_blender.py
  f01: ball centre y=103.5px    f08: y=118.2px
  f16: y=171.2px                f24: y=263.5px
  first third: 14.7px   last third: 92.3px
  PASS: fall accelerates 6.3x — t² survived engine -> spec -> JSON -> bpy -> pixels
```

Вторая проба важнее: тайминг там приходит из `columns.sample_profile`,
то есть падение считает тот самый движок, что писался под Harmony.

## Пять дефектов, найденных на живом хосте

Ни один не был бы найден без запуска настоящего приложения — и это
ровно тот водораздел, о котором говорилось в MINES.md.

1. **`Action` без `.fcurves`.** Blender 5.x перевёл действия на
   слои/слоты, кривые лежат в channelbag страйпа. Код падал с
   `AttributeError`. Теперь `iter_fcurves()` поддерживает оба API —
   версия хоста не зашита в код, который её не проверял.

2. **Глубина конфликтовала с пивотом.** Смещение слоя писалось в
   `object.location.y`, туда же шёл пивот. Части наезжали друг на
   друга. Глубина ушла в ВЕРШИНЫ меша, `location` остался за пивотом.

3. **Канал `x` затирал пивот.** `o.location[0] = value` вместо
   `pivot_x + value`. Мина отложенного действия: для корневой части
   (пивот 0,0) разницы нет, поэтому дефект прошёл бы незамеченным до
   первой руки со смещением по x.

4. **AgX перекрашивал всё.** Дефолтный фильмический tone mapping
   выдавал заданный `(0.92,0.72,0.35)` как `(195,182,158)` вместо
   `(246,221,160)`. Для плоской заливки это чистый вред: цвет из
   палитры перестаёт быть цветом на экране. Поставлен `Standard`.

5. **Порядок обхода вершин решал видимость.** У «руки» нормаль вышла
   +Y (от камеры), у «торса» −Y (к камере) — просто потому, что
   контуры описаны в разном порядке. Рука не рендерилась, и **ошибки
   не было**: с точки зрения Blender всё корректно. Нормали теперь
   приводятся к камере принудительно + backface culling выключен.
   Требовать от художника «рисуй против часовой» — мина, которая
   сработает на первой зеркальной части.

Отдельно: **шестой дефект был в самой проверке.** Три прогона подряд
smoke-тест говорил «рука не видна», хотя рука рендерилась идеально. Я
искал в PNG линейные значения цвета, а Blender пишет sRGB — искал
`(235,184,89)`, в файле лежало `(246,221,160)`. Проверка, которая врёт
про работающий рендер, опаснее отсутствия проверки: она отправляет
искать поломку туда, где её нет.

## Что дальше и чего здесь нет

Есть: тайминг, риг, иерархия, рендер, видео. Всё это от стиля не
зависит.

**Нет рисунков.** Полигонные фигуры остаются полигонными фигурами —
хост тут ничего не меняет. Настоящая рисованная линия в Blender — это
Grease Pencil, и рисовать в нём должен тот, кто **видит результат**
(см. `client/testrig/README.md`: модель, писавшая этот код, изображения
не получает — проверено дважды).
