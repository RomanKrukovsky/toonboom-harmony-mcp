# Как дать проекту настоящие рисунки

Этот файл — для человека с руками и глазами. Код принимает рисунки и
собирает из них анимируемый риг; **рисует человек**.

## Что нужно от вас

Части персонажа отдельными PNG **с прозрачностью**. Редактор любой:
Photoshop, Procreate, Krita, Affinity, Illustrator с экспортом в PNG.

```
parts/
  torso.png      head.png
  arm_near.png   hand_near.png
  arm_far.png    hand_far.png
  leg_near.png   leg_far.png
  parts.json
```

Правила простые, и все они проверяются автоматически:

- **Прозрачный фон обязателен.** Без альфы часть закроет всё под собой
  прямоугольником. JPEG не годится.
- **Одна часть — один файл.** Рука отдельно от кисти, если кисть должна
  двигаться отдельно.
- **Рисуйте часть целиком**, включая то, что заедет под соседнюю: при
  повороте скрытый край выезжает наружу.
- **Разрешение любое.** Размер в кадре задаётся отдельно (`scale`),
  перерисовка в другом разрешении ничего не сломает.

## parts.json

```json
{
  "name": "hero",
  "parts": [
    { "name": "torso", "image": "torso.png", "parent": null,
      "pivot": [0.5, 0.98], "attach": [0.0, 0.0], "depth": 0.2, "scale": 2.0 },

    { "name": "arm_near", "image": "arm_near.png", "parent": "torso",
      "pivot": [0.5, 0.04], "attach": [0.16, 0.40], "depth": -0.2, "scale": 2.0 }
  ]
}
```

| поле | что значит |
|---|---|
| `pivot` | точка вращения **внутри своей картинки**, в долях: `[0.5, 0.04]` — по центру ширины, почти у самого верха. Для руки это плечо. |
| `attach` | куда этот пивот попадает **у родителя**, в единицах сцены. Плечо на туловище. |
| `parent` | к кому крепится. У корневой части `null`. |
| `depth` | порядок отрисовки: **меньше — ближе к зрителю**. |
| `scale` | единиц сцены на 1000 пикселей ширины. Рост персонажа ≈ 2. |

**Про `pivot` — единственное место, где легко ошибиться.** Это доли
(0…1), не пиксели. Если удобнее пиксели, добавьте части
`"pivot_mode": "pixels"` — тогда пишите координаты в пикселях. Путаницу
проверка ловит и говорит прямо, но лучше сразу.

## Проверить набор до рендера

```bash
cd harmony/client
python3 -c "
from artwork import ArtSet, validate, summary
import json
print(json.dumps(summary(validate(ArtSet.load('parts/parts.json'))),
                 ensure_ascii=False, indent=1))
"
```

Проверка ищет то, что **в рендере не даёт сообщения об ошибке**, а даёт
странность:

| находка | как это выглядит без проверки |
|---|---|
| `no-alpha` | часть закрывает соседей прямоугольником |
| `empty-image` | экспортирован не тот слой: часть «есть» и невидима |
| `pivot-looks-like-pixels` | рука вращается вокруг точки в стороне от себя |
| `pivot-outside` | персонаж разваливается в позе |
| `cycle` | Blender падает без объяснений |
| `depth-tie` | части мерцают между кадрами |
| `unknown-parent` | часть висит сама по себе |

`usable: false` означает «рендерить нет смысла». Предупреждения —
на ваше усмотрение: сплошной непрозрачный прямоугольник для фона
законен, для персонажа обычно нет.

## Что происходит дальше

```python
from artwork import ArtSet, image_part_specs
from blender_host import BSceneSpec, build_scene, channels_from_engine

art = ArtSet.load("parts/parts.json")
spec = BSceneSpec(
    name="shot010", fps=24, frame_start=1, frame_end=240,
    resolution=(1920, 1080), parts=[],
    image_parts=image_part_specs(art),
    channels=channels_from_engine(my_animation_channels),
)
build_scene(spec, out_dir=Path("/tmp/shot010"), render=True)
```

Движок таймингов не знает и не должен знать, нарисована часть или
собрана из фигур. Всё, что уже написано — изинги, overlap, сквош,
антиципация, липсинк, камера, континуити, — работает с вашими
рисунками без изменений.

## Проверено на живом Blender

`python3 smoke_artwork_blender.py`:

```

torso: 1432px   arm f1: 489px -> f24: 231px
orientation mark: 24px at (241,91)
background corner: (63,69,80), expected (63,69,80)
PASS: artist PNGs render with alpha, correct orientation,
      and the child part swings around its own pivot (dx=-57.2)
```

Два дефекта, которые нашла именно эта проверка:

1. **Перевёрнутая ось Y в расчёте пивота.** Рука висела ВВЕРХ от плеча и
   уезжала за кадр. Тесты геометрии этого не видели: quad был верного
   размера, симметрия сходилась, UV стояли на месте. Показал только
   асимметричный маркер, нарисованный в углу тестовой руки — поэтому в
   проверке он и появился.

2. **Проверка врала про работающую альфу.** Порог «фон должен быть темнее
   60» падал на корректном рендере: заданный фон в sRGB — (63,69,80),
   законно ярче. Теперь сравнивается с ожидаемым цветом, а не с
   абстрактным порогом.

## Чего код не делает и делать не будет

**Не судит о рисунке.** Похоже ли на нужный стиль, живой ли штрих,
смешно ли — это ваше. Модель, писавшая этот код, изображения не
получает (проверено трижды), поэтому любое её «выглядит хорошо» было бы
выдумкой.

Что она делает вместо этого: проверяет **измеримое** — альфу, пивоты,
иерархию, порядок отрисовки, попадание в кадр, ориентацию — и собирает
риг, который двигается правильно.
